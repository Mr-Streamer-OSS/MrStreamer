# Privacy audit

Every place Mr. Streamer keeps or sends data, checked on 2 October 2026 for slice 6. The [privacy policy](../privacy.md) is written from this page: change the app's data or network behaviour, and update both.

Method. I read the code on `main` after #50, #52, #53, #55 and #56. I ran the development build in Electron 44 on Linux under xvfb, with a fresh profile, against the fake provider and fake TMDB. It logged in, played a channel, opened Movies and a film's details, and waited for the update check. The run recorded every socket the app opened and connected (`strace -f`), Chromium's net log (`--log-net-log`, capture mode Everything), and the main process's fetches (`NODE_DEBUG=fetch`). Then I listed every file the profile held. Separate small Electron 44 runs checked the spellcheck dictionary and crash reports. Mac and Windows are read from code and Electron's documentation; [open checks](#open-checks) lists what still needs those machines.

### Outside the data folder

- **The key that seals the password.** macOS: a Keychain item, "Mr. Streamer Safe Storage". Windows: DPAPI protects the key, which Chromium keeps in the data folder's `Local State`. Linux: GNOME Keyring or KWallet, and without either a fixed key that any program running as the user can use (`index.ts`, troubleshooting). Removing the app or the folder leaves the Keychain and keyring items behind.
- **Downloaded updates.** electron-updater keeps them in `mrstreamer-updater` under the system's cache folder: `~/Library/Caches` on macOS, `%LOCALAPPDATA%` on Windows, `~/.cache` on Linux (`electron-updater` `AppAdapter.getAppCacheDir`, `app-builder-lib` `appInfo.updaterCacheDirName`). On macOS, Squirrel also stages updates under `~/Library/Caches` (not checked).

### Remove subscription

Settings > Subscription > Remove subscription deletes `subscription.json`, `catalogue.json`, `ondemand.json.gz`, `guide.xml` and `guide.json`. It clears the last channel, category and picked versions from `preferences.json`. It keeps `mrstreamer.db`, so favourites, history and progress come back when the same account connects again. It also keeps `metadata.json.gz`, the TMDB key, `updates.json` and the diagnostics log. Checked with a throwaway test against `mainLayer` and the fake provider: before removal, all 11 files; after it, `diagnostics.log`, `mrstreamer.db` (with its `-shm` and `-wal`), `preferences.json` and `updates.json`. The database still held the `server|username` key and no password.

### Uninstalling

Nothing deletes the data folder.

- Windows (NSIS): `deleteAppDataOnUninstall: false` in `electron-builder.yml`. The uninstaller removes `%APPDATA%\Mr. Streamer` only when started with `--delete-app-data`, and never touches `%LOCALAPPDATA%\mrstreamer-updater` (`app-builder-lib` `templates/nsis/uninstaller.nsh`).
- macOS: moving the app to the Trash leaves the data folder, the Keychain item and the caches.
- Linux: removing the deb or deleting the AppImage leaves everything in the home folder; package managers never touch it.

Deleting the data folder removes everything above except the Keychain or keyring item and the update cache.

The run saw nothing else: loopback traffic to the fakes and the playback proxy, the artwork hosts, `image.tmdb.org` and the feed. Chromium also connects UDP sockets toward Google's public DNS address (`2001:4860:4860::8888`, port 443) and toward resolved addresses, to check reachability and pick a source address; the trace shows nothing sent on them before the socket was reused for a local DNS query. Every host name goes to the system's DNS resolver, so the network and its DNS provider see which servers the app contacts. Before #50, Linux also fetched a spellcheck dictionary from `redirector.gvt1.com` on first start.

No analytics, telemetry or crash upload exists: nothing in the code calls `crashReporter.start`, and the only network clients are the Xtream adapter, the playback proxy, the TMDB client, update discovery and electron-updater. A crashed window in a minimal Electron 44 app wrote no report on Linux.

## The login

- Every provider request carries it. An https address never sends it over http, redirects included, and an address without a scheme asks before trying http (#53, #56, [architecture](architecture.md#the-login-on-the-wire)).
- Errors that reach the window, the console and the diagnostics log cut every address to its origin (`withoutAddresses`). `apps/desktop/test/credentials.test.ts` checks the window's errors and the log after failures whose messages quote the full address.
- The window never sees provider addresses: playback goes through a loopback proxy with a random token, and ffmpeg reads from that proxy or stdin, so the login never reaches a command line ([architecture](architecture.md#playback)).
- At rest the password is sealed (see above). The server address and username aren't.

## What the publisher controls

The publisher is Wout Stiens, in Belgium. The app sends him nothing. What he runs or chooses:

- **The code and its releases.** The repository, GitHub Releases and the update feed on GitHub Pages are hosted by GitHub, Inc., which processes visitors' requests under its own privacy statement. Pages and Releases give the publisher no request logs; Releases show a download count per file.
- **The built-in TMDB key.** TMDB sees every user's requests under the publisher's API account. The publisher gets no per-user data from it.
- **The domain `mrstreamer.app`.** DNS and redirects run on Cloudflare (`walt` and `bethany.ns.cloudflare.com`). `https://mrstreamer.app` and `https://mrstreamer.app/privacy` answer 302: the site to the repository, the policy to `docs/privacy.md` on GitHub. Cloudflare sees those requests.
- **Email.** `hello@`, `security@` (`.github/SECURITY.md`) and `privacy@mrstreamer.app` go through Cloudflare Email Routing (`route1-3.mx.cloudflare.net`) to the publisher's mailbox. Wout configured the `privacy@` route on 2 October; delivery isn't tested yet.
- **Issues.** GitHub Issues are public. The issue template and troubleshooting ask people to leave out their server address and login.

He doesn't control the provider, artwork hosts, TMDB's or GitHub's own processing, the system keychain, or the Microsoft Store.
