# Slice 3.5: foundation before movies and series

Status: in progress, started 30 September 2026. Stages 1 to 5 done: baseline, workspace, Effect on the guide, event log, and the remaining services on Effect.

Outcome: a small monorepo, Effect services in the main process and an event log for favourites and watch history, before slice 4 adds movies and series. Viewing behaviour stays the same.

## Start here

- The [plan](https://65hwnugrlbni.postplan.dev) records the decisions and stages; the [foundation proposal](https://56882irfsifg.postplan.dev) is the reasoning behind them.
- Each stage is one pull request. It merges when CI and the pre-PR audit pass, and a nightly follows when the app changed. Wout tests the result at the end.

## Decisions

Settled with Wout on 30 September:

- **Going back to Stable:** Stable 0.0.1 shows no favourites or history once they live in the database. No compatibility copy or reconciliation.
- **Events:** favourites and watch history. Volume, mute, last category and last channel stay in `preferences.json`.
- **History:** import today's recent channels and favourites once; keep every watch event; no clear-history feature yet.
- **After the import:** favourites and recent channels are removed from `preferences.json`; the settings stay in it.
- **Per account:** events carry the account. Switching accounts hides the other account's favourites and history instead of deleting them.
- **Effect:** version 4 release candidate, pinned. **Database:** the built-in `node:sqlite` (Electron 44 ships Node 24.21 with SQLite 3.53.4).
- **Layout:** `apps/desktop`, `packages/contracts`, `packages/core`; the renderer stays in the desktop app; no task runner.
- **Effect breadth:** every main-process service, in stages; playback's lifetime in scopes, its streaming code unchanged. **Renderer:** React Query and Zustand, no Effect.
- **Order:** no waiting for slice 3 acceptance or a Stable 0.0.2; one hiccup for current users is acceptable.
- **Diagnostics:** a local rotating log with durations, failure types and conversions; no URLs, logins, network or UI.
- **Performance:** nothing more than 10% worse than the slice 3 baseline below.

## Baseline

Nightly `0.0.2-nightly.20260930.23` (`1615e59`, slice 3 with #7), measured on 30 September with `test/e2e/measure-app.ts`: the fake provider with 13,000 channels, about 2,000 guide channels and a continuous 720p H.264 and AAC stream, three runs where it repeats.

| Measure                           | Mac mini (M4), DMG | Workbench VPS, deb under Xvfb |
| --------------------------------- | ------------------ | ----------------------------- |
| Cold start to Home                | 424 ms             | 1,236 ms                      |
| Time to picture                   | 1,024 ms           | 1,382 ms                      |
| Channel switch                    | 776 ms             | 1,133 ms                      |
| Guide open                        | 26 ms              | 69 ms                         |
| Guide list of 13,000              | 17 ms              | 38 ms                         |
| Search, typed to programmes shown | 260 ms             | 272 ms                        |
| Idle CPU on Home, preview playing | 15.6% of a core    | 56% of a core                 |
| Idle CPU on Home, stopped         | 1.0%               | 0.8%                          |
| Memory on Home, preview playing   | 797 MB             | 910 MB                        |
| Memory on Home, stopped           | 779 MB             | 795 MB                        |
| Installed size                    | 251 MB             | 285 MB                        |

The VPS decodes in software on a shared machine; its runs vary by up to 20%, so compare medians from the same script on the same machine, and measure again before calling a result over budget. Differences under 20 ms or one percentage point of CPU are within noise.
