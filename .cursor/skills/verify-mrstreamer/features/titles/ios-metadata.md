# iOS metadata

On iOS, TMDB is asked with the viewer's own key, kept in the Keychain (`metadata.tmdb`), else the app's built-in `EXPO_PUBLIC_TMDB_KEY`. The Keychain is read only once a listed title has a TMDB id or Settings shows TMDB, so a Demo touches it only from Settings; while it won't answer (locked before the first unlock) the app's key is used and it is read again next time, so a saved key is found without a relaunch. Saving or removing the key closes the metadata store and starts a new one, and lets go of details' TMDB answers asked with the old key, never saving one that arrives after the change, so a refused key stops fetching only until it changes. A removal whose Keychain index write fails after the key itself is gone counts as done. `metadataStanding()` in `apps/ios/src/titles.ts` gives Settings and diagnostics one state: reading the Keychain (`reading`), waiting for the lists and metadata demand (`waiting`), no key, no listed title with a TMDB id, refused, not answering (a run ended before every listed title had an answer), asking, or answered, with `known` of `wanted`; `retryMetadata()` asks again. `detailsOf` answers with `about`: TMDB's answer, the provider's facts because the title has no TMDB id or TMDB doesn't know it, or there is no key, TMDB refused it or didn't answer, with `savedAt` when an older saved TMDB answer shows. Saved answers show without a key too. While a saved answer past TMDB's refresh shows and TMDB is asked again, the early details say `asking` with its `savedAt`. A key change bumps the metadata version, so open details read again. A non-final TMDB answer is never kept, so details' Try again asks again. `apps/ios/test/metadata-recovery.test.ts` drives the real account and titles owners against the fake panel and TMDB: the key through a relaunch and its removal, saved facts kept once the only key goes, a locked Keychain read again, a season read rejected without showing episodes when its login changes during the Keychain wait, a refused key replaced and details asked with it let go, an old key's late details answer left unsaved so details ask with the new key, a removal whose index write failed, a 151-day-old saved answer shown dated (asking, then unavailable) while TMDB is offline with browsing intact, a panel listing no TMDB ids, Try again, and an unknown title. Settings > TMDB (`settings.tsx`, `Tmdb`) shows the key as Add, This build's or Saved (Replace or Remove, which falls back to the build's key), the status, red when refused or not answering, the titles TMDB gave then, and Try again while it isn't answering. TMDB's logo and notice stay in About and always show, since saved TMDB facts outlive a key. Details' About line (`details-screen.tsx`, `aboutReason`) says Provider details only or Saved TMDB facts from its date, and why (or Asking TMDB again), with Try again while TMDB isn't answering. `apps/ios/test/diagnostics.test.ts` covers key management, the no-key/refused/unavailable/answered Settings states, and the details fallback and retry lines. It does not cover the Settings reading, waiting or fetching states. Native Keychain behavior and the screens on an iPhone need the Mac.
