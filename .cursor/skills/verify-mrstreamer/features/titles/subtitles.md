# Desktop file and online subtitles

Online subtitles are configured in **Settings > Subtitles > Online search**. During local movie or episode playback, **CC > Search subtitles** searches the enabled services. Choose a result there, or select a saved result under **Saved for this version**. Every subtitle control of a title is in that panel: **Timing** steps a file track, or edits the downloaded result's offset, with drift and the frame-rate conversions under **Drift and frame rate**; **Look** sets size, background and position; **Try the next result** sits with the search; **Settings** opens Settings > Subtitles on Online search. **Forget downloaded subtitles** clears that file's downloaded results. The **Speed** button beside Sound sets the speed and nothing else. While a TV plays the title, CC is the small menu, with Subtitle timing and Subtitle look listed greyed.

For file subtitles, select a text track several minutes into an MKV, then reopen it with that track chosen and resume. Use a fake provider that delays range answers: upcoming text must show while recovery of earlier lines is still loading, and a long-lived line that began earlier must still arrive when recovery completes. "Subtitles loading" at the top right and "Loading" beside the chosen track in CC show only while no line the run has is due at the position, as Earlier/Later (G/H) time it: a line on screen silences both, a pause between lines while recovery runs brings them back, and a timing change while paused updates both at once. After the feed ends or breaks, "Unavailable" shows once its last line is over. An exact live text line still held in the feed's bounded memory is sent once, including across two quick skips with an intervening cancelled run; new text at the same timestamp still arrives. A new run fills lines missing from an old trimmed live buffer. Recovery failures for limit, unreadable and network keep known text; replacing the file clears it. The 35-second loading deadline keeps text and its feed active, ending only the loading state as unavailable, which is said only where no line is due; packet tracks still stop and clear at that deadline. PGS and DVB still wait for their recovered decoder state. Public service cases are in `apps/desktop/test/titles.test.ts`, with renderer cases in `apps/desktop/test/renderer/title-subtitles.test.ts`. MP4 text reads its own samples through the run and downloaded subtitles are whole files, so neither needs the MKV history scan.

The titles baseline does not configure online subtitle services. For online proof, use the existing Electron/CDP harness in `apps/desktop/test/e2e/app.ts` with fixture service responses at the external API/download boundary. Require zero service requests after configuration or opening CC, a request after Search, and downloaded cues over a picture that keeps playing. Edit timing, switch cached results with no new download, then restart the app and require that the same exact file restores its text and correction without a service request. Another file version must start without that correction. Choosing Off or a file track during restore must leave the saved result available. Choosing Off, a file track or a saved result during a download, or pressing C, must cancel that download and ignore its late success or failure. Forget must clear the download without changing the global subtitle language.

Choose Off or a file track, leave and reopen the same file: the saved result must stay listed and not show, the subtitle language in `preferences.get` must be what it was before that choice, and choosing the result must show it again with no service request and survive the next reopen. The same choice with nothing saved held, as during a first download, is remembered as the language for other titles. An explicit download must restore after a restart even with the subtitle language Off. Change the fixture file's strong ETag and read the session's playback address once more: the downloaded cue and its saved row must leave while the picture and the file's own tracks go on, and Search must be unavailable until the title is opened again. A provider file small enough to be held whole is not read again by a skip, so the skip alone does not establish a replacement.

Public service and IPC cases are in `online-subtitles.test.ts`, `online-subtitle-playback.test.ts`, `subtitle-services.test.ts` and `saved-subtitles.test.ts`; renderer cases are in `renderer/downloaded-subtitles.test.ts` and `renderer/online-subtitle-panel.test.ts`. They include the per-file Off mark and the language preference it leaves alone, the choice main follows when it saved a download the window had already turned away from, an episode's rights through an unchanged and a changed refresh and after its series' details were no longer kept, Off kept while the provider gives no answer, C showing a turned-off result on a file with no track of its own, the panel's timing, look, next result and Settings link, its Down order, Escape from the page after a pointer pick, focus in and back, and the `playback.fileReplaced` event. `renderer/speed-menu.test.ts` covers the Speed button. These contracts supplement the built-app flow. Service fixtures establish no real account, quota or external-service acceptance.

Subtitle, sound and title languages share `TITLE_LANGUAGES` in `packages/core/src/ondemand/languages.ts`, so Settings, CC's search language and the title filters list the same ones. Arabic is `ar`, shown as العربية: SubDL is asked for `AR` and may answer `Arabic` or `AR`, OpenSubtitles is asked for and answers `ar`, and file tracks tagged `ara` or `ar` read العربية. Downloaded files are read as strict UTF-8 first; an Arabic file that is not valid UTF-8 is read as Windows-1256 by `subtitleTextBytes` in `packages/core/src/subtitles/text-file.ts`, and other languages' non-UTF-8 files, like files with no valid cues, are refused as unsupported. iOS still reads downloads as UTF-8 only. Each cue line takes its direction from its own text (`unicode-bidi: plaintext` in `styles.css`), so Arabic reads right to left with its punctuation at its end. Like Dutch, Arabic subtitles, so an `(AR)` version reads as the title's own sound with Arabic subtitles and ranks above an unmarked one for other viewers. iOS offers Arabic from the same list; Arabic in its cue overlay is unproven. `subtitle-services.test.ts` covers the codes, the UTF-8 text and a Windows-1256 download from each service, and `subtitle-text-file.test.ts` the encoding rule; for joined letters and direction, show a downloaded Arabic cue in the built window and inspect the screenshot.

Downloaded text and timing belong to the exact file and play locally. Receivers keep supported file tracks. Removing a subscription retains its saved subtitle data unless the viewer also deletes its viewing data. After a catalogue refresh, or once 200 other titles' details were read, the next subtitle command of a playing episode asks the provider for its series' details once: the same listing keeps the saved result, timing and search, another listing ends them until the title is opened again, and no answer refuses them until the provider answers. Off or a file track over the saved result is kept for the file playback still holds, with or without that answer. A failed save there is a finding, not proof.
