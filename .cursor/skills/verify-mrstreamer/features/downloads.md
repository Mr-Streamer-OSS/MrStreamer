## Desktop managed folders and selected controls (0.0.24)

The public Downloads commands expose the selected household folder, move selected finished copies, cancel an in-flight move, and pause, resume, retry or remove explicit selections. Folder selection affects future transfers; existing copies move only on request. Commands return a failure rather than success for unavailable destinations or failed writes. Bulk results name successful and failed IDs separately.

Use an isolated profile and disposable folders. Keep a movie with subtitles and artwork plus an unrelated episode and recording. Choose a folder, relaunch and check the choice. Move only the movie, watch it offline and verify its exact ID, details, artwork, subtitles and private resume position. Cancel a move, then disconnect the destination during cleanup and relaunch: the original must remain playable; after reconnection and restart retry the move. Repeat with a missing, full and read-only destination. Bulk-delete only the movie and verify the episode, recording and personal progress remain. Verify picker cancellation, keyboard selection, confirmation, readable error/retry controls and every supported translation when the UI is integrated.

In the window, `apps/desktop/src/renderer/src/features/downloads/DownloadsPage.tsx` shows **New downloads go to <folder>** under the heading with **Change folder** (`downloads.chooseFolder`; null changes nothing, a refusal shows its error as an alert). Every row has a round checkbox named `Select <name>`, episodes `Select <series> · <episode>`, and a series header a box that selects all its copies and is indeterminate while only some are. With any selected, the `[data-selection]` group (`<n> selected`) offers Pause, Resume, Retry, **Move to <folder name>** and Delete, each sent only for the selected rows it fits through `downloads.bulk` (a move is its `move` action), which answers for each ID. Delete turns into **Delete <n> downloads** and needs a second press; blur or Escape reverts it. The `role="status"` line says **<done> of <total> done**; failed rows show their error and stay selected, and **Try again** reruns only the failed IDs. A row in `storage.moving` reads **Moving to <folder name>** with **Cancel move** (`downloads.cancelMove`) instead of Delete. **Done** clears the selection; when the bar disappears with focus on it, the `Downloads` heading takes focus. Renderer proof: `apps/desktop/test/renderer/downloads-selection.test.ts` (happy-dom, IPC test double), not a built app. Move and folder failures use sanitized messages in all five supported languages. The selection bar wraps long destinations and actions without a fixed height. Done dismisses the result but keeps admission while a bulk call is pending; selecting again shows disabled bulk actions until that call settles. Cancel move also cancels the remaining moves in that selection.

Source proof lives in `apps/desktop/test/downloads.test.ts` through the public Downloads command seam, with real temporary files and fake provider media. Full/read-only write failures are injected at the filesystem call; they do not qualify physical removable drives. Recovery proof retains the persisted interrupted-target marker after failed cleanup and restarts the runtime. Directory flushing is used on Unix; Windows flushes copied files but cannot open directories for flushing through this implementation. Native Windows/macOS, physical disk loss, power loss and the integrated UI require separate runs. No native or UI acceptance follows from command tests alone.

Moves reserve a fresh UUID folder in durable metadata before creation. The copy ID and private progress stay unchanged. Recovery transfers incomplete-target and old-source cleanup into durable pending records before clearing move markers. Unavailable folders stay tracked independently of later moves or deletion of the playable copy. New move folders carry an ownership token, so changed parent device/inode after remount does not prevent cleanup; a mismatched token prevents deletion. Legacy markers without tokens retain parent checks or remain for manual cleanup. Pending folders are excluded from the default-root sweep. SQLite FULL applies only to move intent, location commits and cleanup bookkeeping, restoring the prior connection setting; ordinary queue and progress writes retain the existing policy. The source service tests do not emulate physical power loss or native filesystem durability.
