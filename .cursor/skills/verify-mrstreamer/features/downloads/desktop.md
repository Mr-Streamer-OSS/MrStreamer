# Desktop downloads baseline

## Driving it with Electron CDP

Run `xvfb-run -a pnpm verify:desktop downloads` after `pnpm build` (no Xvfb on macOS or Windows). It starts the app on an English system; `pnpm verify:desktop downloads fr-FR`, or another interface language, starts it on a system in that one, so System default shows it, and looks for each control and message in that language. The scenario in `scripts/downloads.ts` starts the built app three times on one profile, with the fake provider, fake TMDB and a loopback picture server, and drives it with pointer and key input:

1. Connect; download the two-sound-track movie from its details and S1 E2 of the Formats series from its row, until **Watch offline** and **Downloaded** show.
2. Hold the long-subtitles movie's file at 40 kB, download it, then Play the index-at-the-end movie of the same subscription. Require a moving picture, `waiting` for the held download, and at most one provider file at once; after leaving, require every download complete. Then hold the broadcast-recording movie's file, download it, play a channel from Search and press Escape for Home's muted preview: the download waits, and its details opened from Search read Waiting for playback · Cancel, which cancels it.
3. Download the missing-file movie, Retry it from the details (a new file request), cancel a held download and delete the failed one on the Downloads page.
4. Quit, stop the provider, TMDB and pictures, start again. On Downloads, play the movie offline, skip forward, choose the other sound track, leave; play the long movie, choose its French text track, skip to 40 s, require cues and a caption on screen, leave and, as soon as main's list keeps where it was left, press Watch offline: it resumes near there though the row may not show it yet (`resume.shownAtResume`), and the row shows it after.
   Along steps 2 and 3 the top bar's notice is read and pressed: a percentage while the long movie transfers; Waiting over the playing title, where Tab and Space on it leave the title, saving where it got to, and open Downloads with no details over it; Waiting over Watch, where Tab and Enter on it close Watch over Downloads and the download takes the connection on; Waiting behind Home's preview; beside Search and Downloads among the pages at the window's width, Enter on it opening Downloads, which then shows no notice; the folded Downloads button marked on its page, and Space on it from Movies; Download stopped with the failed download alone left, pressed back to Downloads; nothing once only copies are left. Over the details, with Back in the pages' place, the bar is narrowed 20 CSS px at a time until Download stopped keeps its arrow alone, and the held movie's percentage must show there as it starts, nothing resized. At the narrowest width where the folded Downloads says the percentage, Tab to it and cancel the transfer from its row with the pointer: Download stopped goes to its arrow with the same button in focus; on Movies, Tab to it again, point at it for the tooltip, then the window's own width (words back) and the narrow one (arrow again) keep that focus, and Enter opens Downloads. Every page draws its own bar, so opening another page starts the keyboard over. While it transfers, waits and stopped, the bar is laid out at an emulated 960 and 760 CSS px (the window's least width is 960), and Download stopped over Settings at 960, 520 and the measured Back fold width: each read fails the run when a page's name, Back or a control is cut. A MutationObserver records every word the visible notice said as `notice.said`, empty while the arrow stands alone.
5. Remove the subscription in Settings, quit, start again. Connect shows Downloads; the page lists all copies with "Subscription removed, copy kept", local artwork loaded and progress. Play the episode and resume the long movie. Remove the two-track movie's file from the run's profile, Watch it offline, require **Download missing**, press Back and require its row to say the file is gone, with Delete and no Watch offline, before main's list is read. **Add subscription** returns to the form.

`network-hook.cjs` is loaded into main with `NODE_OPTIONS=--require` for this scenario only: it writes every outbound TCP connection and UDP send to `main-network.jsonl` and answers the image CDN hosts from the run's picture server. The window's requests come from CDP `Network.requestWillBeSent`. Each local playback window must show no main connection and no window request except the loopback proxy's `/title/` and `/source/` routes, `mrstreamer:`, `data:`, `blob:` and `file:`. Proof is in `.local/verification/downloads-<unique>/`, or `downloads-<locale>-<unique>/` in another language: `proof.json` (its `locale`, actions, observations including `notice` (each bar read with the pages' names, `room` and `needs` in CSS px, whether a name or control is `clipped` or `overflows` the bar, and the Downloads controls beside Search; `fromTitle` with the progress main saved, `fromWatch`, `<state>AtWidths`, and `stoppedBesideBack` with the measured Back room and required width at each probe), `preemption`, `waitingBehindPreview`, `seek`, `soundTracks`, `embeddedSubtitleCues`, `captionShown`, `resume`, `standalone`, `offlinePlayback`, `playbackWithoutSubscription`, `missingCopy`, each start's checked `starts` and a `mainNetwork` summary), screenshots with accessibility trees, `main-network.jsonl` and `electron.log`.

A download asks through the same `Provider.request` as playback, so a playlist film's Referer holding the link's token reaches no other origin whole, and no login value the rule recognizes follows an https redirect to http (`playlist-credentials.test.ts`).

## Gotchas

Fixture names come back from TMDB as "Original 100000" and similar: the scenario finds rows by the download id main lists, never by provider names. The 20-second fixture is all credits by the 30-second rule, so resume is proved on the 150-second one. The first track of the long-subtitles fixture is pictures, drawn from a metadata track: text cues need its French track. Home's muted preview is playback too, so a download of that subscription waits while Home shows it. The proof uses fixtures and a development build on Linux; disk-full and folder failures are injected at the disk boundary in the service tests, not provoked on a real disk. Native macOS and Windows installs, a real provider and real disk exhaustion need their own checks. The fixtures say each file's size, so the notice's bytes and Starting are covered by the renderer tests only. Layouts below 960 CSS px are CDP viewport emulation, standing in for a zoomed window. The update notice and the TMDB ring beside the notice are not shown in this scenario; the bar folds by what it measures, so they count as any other width there, and the renderer test dismisses Update with its layout supplied. The arrow tries its words again when the pages' room grows, the words change or the interface language does, measured before the bar is drawn. On Windows, the [installed upgrade check](../../../../../docs/contributing/testing.md#installed-upgrade) downloads two movies and the selected S1 E2 file on the actual stable release before installing the candidate over it. Stable plays the copies, observes saved subtitle timing and cues, and leaves nonzero local movie progress. Candidate entry requires the same three completed IDs, saved details, artwork and progress before any playback, with no replacement download; copied playback must resume stable's saved position. The same candidate then restarts, retains those copies, removes the subscription and plays them with the fixture services stopped and the app, bundled ffmpeg and ffprobe proven blocked from the network. The restart is not another upgrade. Acceptance requires the actual Windows run; stage-contract stand-ins do not prove the installer transition or installed codec recovery.
