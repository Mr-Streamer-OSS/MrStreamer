## Background lifecycle

`apps/desktop/src/main/index.ts` keeps active, queued and waiting downloads alive after Close, destroys their renderer, and exits on Windows/Linux once neither runnable downloads nor recording obligations remain. Paused, failed, missing and complete rows alone do not keep it running. The native menu contains nonzero counts only (no percentage), Open, **Pause downloads**/**Resume downloads** and explicit Quit, labelled with … while it will ask. Downloads-only Pause on Windows/Linux reads **Pause and quit** and awaits the durable save before exit. A failed save opens the window with an error and leaves the command retryable. Quit asks through `window.leaveAsked` while runnable downloads or live recordings remain; `window.quit` confirms, and runtime disposal settles the transfer while retaining partial data. macOS Close retains the app; Quit remains explicit. Add, Retry, Resume and Resume all keep termination pending until their operations settle; exit decisions invalidate overlapping reads and read the public download list again. A failed read remains visible with Try again and deliberate Quit through awaited cleanup. Tray Quit reopens Downloads before asking, so Home never takes its connection. Menu updates follow counts and labels, not progress bytes. macOS uses a Retina template mark and retires it once no downloads or live recordings remain, retaining it for paused downloads. Actual transfers, recording capture and receiver playback use app-suspension prevention with display sleep allowed. There is no login startup, service or computer wake.

Build, then run `xvfb-run -a node .cursor/skills/verify-mrstreamer/scripts/downloads-background.ts` with `MR_STREAMER_VERIFICATION_OUTPUT` set to an owned evidence directory. The scenario queues fixture movies through details, pauses them and requires Close to exit, restarts on the same profile, resumes through the public command and closes in the same turn as its answer, observes no page target while the app stays alive, and requires both files complete before automatic exit. Native tray keyboard/screen-reader behavior, save refusal, manual sleep, OS wakefulness, Windows and macOS require separate matching runs. `apps/desktop/test/renderer/quit-dialog.test.ts` proves the download-aware Quit question; the native menu labels have no automated check.
