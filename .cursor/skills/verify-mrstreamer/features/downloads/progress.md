# Default local-copy progress

## Default local-copy progress

From 0.0.24, `apps/desktop/src/main/platform/profile-copy-progress.ts` keeps resume positions in the existing database under the active Default profile, copy kind and local copy ID. Listing completed downloads or opening a download or recording seeds Default’s missing position from its legacy document once, including absence and zero; recording lists do not seed positions. Incomplete downloads return null progress without reading or seeding personal storage. Other owners start with no legacy position; only explicit playback writes replace a seeded position. Provider removal, another copy of the same title/channel, artwork, transfer and recording-inventory writes cannot replace that personal position. No additional profile or switching UI is exposed. Failed personal writes report failure and retain the last saved position. The title controller retries refused download saves every 10 seconds while its renderer lives, including after the player closes; a newer save supersedes the older retry. Each retry first reads the inventory and stops when that copy is gone or no longer complete; a failed inventory read stays retryable. Recording retries belong to the main runtime, which retains pending progress and retries on its checks, including when schedules cannot be read. Pending retries are in memory: restarting the app before a successful retry retains only the last durable position.

Focused public runtime tests in `apps/desktop/test/downloads.test.ts` and `apps/desktop/test/recordings.test.ts` cover migration, restart, zero reset, stale inventory writes, provider removal and refused SQLite writes followed by retry. They use temporary profiles and fake providers; they do not prove keyboard playback, translated resume controls, native playback or installed upgrade behavior. For candidate acceptance, run the existing isolated UI journey, resume a migrated copy, seek back to zero, leave and reopen it after a restart and subscription removal, then verify keyboard focus/readability and a supported translated interface. Retain candidate build identity and screenshots; service tests alone are not UI proof.
