# Desktop pause and order

Run `xvfb-run -a pnpm verify:desktop downloads-queue` after `pnpm build` for the queue's controls (`scripts/downloads-queue.ts`). It starts the built app twice on one profile with the fake provider, fake TMDB, a loopback picture server and `network-hook.cjs`, and the window resolves no host but loopback (`--host-resolver-rules`). It queues the missing-file movie, which fails, then three movies the provider holds, from their details. It pauses the transfer with Tab and Space: the row moves and the keyboard stays on its Resume. It moves the last one up with Tab and Enter: Up is then off, Down has the keyboard and the provider is asked nothing new. **Pause all** with the pointer pauses every one, offers Resume all and frees the provider's connection, and the bar's notice on Movies says Paused, muted. It resumes the one moved up and plays the index-at-the-end movie of the same subscription from its details: the resumed one waits, the paused ones stay paused, one file at a time, and after Escape the connection goes to the resumed one only. The next start must show the pauses and the order kept. **Cancel** takes the transfer's folder with it. The second movie's file is then replaced at the provider and resumed from the keyboard: its row must say `started again, the file changed` and the copy's SHA-256 must be the new file's; the first copy must match the provider's file. With `--previous <executable>`, an earlier build's executable starts on the same profile between the two. For 0.0.19, check the public AppImage against the release's `SHA256SUMS.txt`, unpack it into ignored scratch with `unsquashfs -o <offset>` (the ELF header's section table end) and pass its `mrstreamer`. It must list every download, transfer the paused first one in the order added (going back can't keep a pause or a place), retry the failed one with **Retry**, keep a copy's progress from **Watch offline** and leave the second one mid-transfer at quit; the next start must find the second one paused again and the one moved up first among those waiting. A packaged build takes no `--require`, so main's connections are recorded for this build's starts only. Proof is in `.local/verification/downloads-queue-<unique>/`, or `downloads-queue-previous-<unique>/`: `proof.json` (`pausedTransfer`, `movedFromKeyboard` and the `keyboardLog` of focus and row order around it, `allPaused`, `noticeAllPaused`, `whilePlaying`, `afterPlayback`, `previous` and `previousStart`, `afterRestart`, `cancelled`, `changedFile`, `final`, `mainNetwork`), screenshots with accessibility trees, `main-network.jsonl` and `electron.log`.

The fake provider holds a file once per request, at its byte: a download resumed from that byte isn't held again and finishes at once. The queue scenario therefore holds a download further on before playback ends and before each start, or it would finish between two reads. A pause answers only once main has written where the transfer stopped, and main's list can arrive before or after that answer.
