# Desktop layout and progress profiling

Long-series progress checks use 520 episodes in 20 seasons, 2,000 unrelated complete copies and one advancing transfer. Unrelated progress must leave the selected episode statuses and details view unchanged; progress for that exact subscription/file must update its still bar, facts and action. Batch add/cancel/retry reads current queue snapshots after awaited commands, including a new completion or removed missing copy. `renderer/series-download.test.ts`, `downloads.test.ts` and `episode-rows.test.ts` preserve those contracts. `download-performance.probe.ts` is a separate React/happy-dom diagnostic, not native paint evidence.

For download-progress profiling, run `node apps/desktop/test/e2e/download-performance.ts --app-dir <frozen app directory> --executable <Electron> --revision <sha> --output <new evidence directory>` serially for each build. It seeds 2,000 completed records while the app is closed, then drives a 520-episode series while a real transfer advances. Retain all 30 content/scroll samples, main snapshots, CPU profiles, traces and matching-row positive control. Task/script time and a subsequent animation-frame callback do not prove physical paint latency or retained-heap savings. The functional Downloads driver waits for a pointer-reachable control after Search closes; a mounted control can still be behind its closing overlay.

The folded-page check probes 760 down to 520 CSS px in 20 px steps and records `notice.foldedWidth`, requiring the actual folded Downloads control and current-page marker before exercising its pointer/keyboard paths. Header copy changes the width where folding starts; 760 px alone may still fit all page names. The existing 960/760 layout checks remain required separately.

The Back/notice fold probe checks 960 down to 320 CSS px in 20 px steps, stopping at the first arrow-only notice. System fonts and native window-control insets change that boundary; text that fits at 520 px is valid. Every probed width must still fit Back and all controls, the shorter percentage must regain its words at the same width, and Settings must fold there too. The separate 520 px Settings check still requires an unclipped bar.
