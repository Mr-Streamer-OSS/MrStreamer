# Shared viewing preferences

Settings groups viewing preferences under Playback, Live TV, Movies and series and Subtitles. See the [Settings control inventory](settings.md) for destinations and local search. Player track choices save the same language preferences. CC also saves subtitle look. Volume/mute, CC subtitle look, Live TV's List/Guide choice and Home customization show local pending choices until persistence answers; unrelated saved fields leave those choices intact. A failed save reports its setting and resolves that choice against the latest committed state.

After building, run `pnpm verify:desktop preferences` (under `xvfb-run -a` on headless Linux). The isolated fake-provider/TMDB scenario sets French audio in Settings, plays the two-track fixture, selects its Spanish track, reopens Settings to observe Spanish, edits subtitles and next episode independently, and restarts to verify all three choices. Inspect its Settings and player screenshots with `proof.json`. `language` checks the separate interface-language owner, `live-tv` checks shared playback, and the [Privacy](privacy.md) loopback scenario checks consent-only saves.

Viewing preferences belong to the admitted [viewing profile](profiles.md), including its TMDB key, title/adult/audio/subtitle choices, volume, Home rows and live-view preferences. Default retains `preferences.json` and its existing path compatibility; private owners have separate preference files. `analyticsEnabled` alone overlays the existing installation Analytics consent owner, so a profile edit changes the consent telemetry actually uses. Interface language has its own Settings methods; guides, updates and storage directories keep their separate installation owners. The main IPC get/update replies and `preferences.changed` carry the same process-local `{ revision, preferences }` snapshot. The renderer query cache accepts only increasing revisions, including React Query's own late query completion. Field changes reset adult-sensitive library/guide/watchlist reads and refresh on-demand/watchlist metadata once. Volume/mute, subtitle look, list/grid and Home drafts never write the authoritative cache. Players use this path outside React; composition owns and detaches its event listeners.

`apps/desktop/test/preference-publication.test.ts` covers committed-owner composition, ordering, concurrent unrelated edits, consent-only saves, partial commits/defects, unreadable snapshots and nonblocking reads during consent/reconfiguration. `profiles.test.ts` proves private preferences across restarts, installation Analytics opt-out from profile B across switch/restart, and explicit private-file read refusal. Renderer `profiles.test.ts` proves late-owner replies/events and language continuation refusal through production modules with scripted transport. Renderer `preference-publication`, `subtitle-look-preferences`, `guide-grid`, `home`, `settings-tracks`, `watchlist` and `analytics-setting` cover delivery races, effect freshness, listeners, pending drafts and public controls. `preferences.test.ts` covers persisted-file compatibility. No revision is written to Preferences or the iOS schema. Installed prior-stable/candidate, native audio/GPU and real-provider acceptance remain separate checks.

CC and Settings share a pending look editor. Rapid size/position/background picks merge against that intent even when an earlier committed look arrives or either editor remounts. A latest failed write reads back through the committed owner; an older failure cannot roll back or report over a newer choice. The composed `subtitle-look-preferences` cases install real `syncPreferences(player.hydrate)` and exercise these races through the public CC and Settings controls.

Desktop command overrides use the optional `keyboardShortcuts` preference through the existing profile-owned preference publication route. The shared command catalog in `apps/desktop/src/renderer/src/app/shortcuts.ts` owns defaults, binding validation and dispatch guards; players read only committed preferences. Unknown command IDs survive upgrades, absent commands use defaults, and an invalid known override set falls back to defaults in both the reference and dispatch while its saved values remain available for repair or reset. Reset all saves an empty override record; a single reset that would conflict with another saved binding is visibly refused before writing. Renderer `shortcuts.test.ts` exercises conflicts/reservations, input protection, repeat policy, actual title playback after a remap, failed saves, reset and refusal of a late old-profile save. Its fresh-cache read is contract coverage, not disk-restart proof. Settings > Playback > Keyboard shortcuts (`KeyboardShortcuts` in `apps/desktop/src/renderer/src/features/settings/SettingsPage.tsx`) is the reference and editor: each command's keys are one button that captures the next key, Escape cancels without closing Settings, Tab leaves, refusals show under the row, and a failed save keeps the committed keys with Try again beside the row. Its renderer test drives capture, refusal, failed save, retry and reset through the page.

For shortcut acceptance, use an isolated built app: remap Pause, observe the new key pause/resume an advancing movie and a rewind-capable live channel, confirm old keys stop doing so, switch profiles and restart, then inspect each profile's binding. Refuse a save and require the previous committed binding to keep working with visible retryable feedback. Reset and require default dispatch and retained keyboard focus. Tab through capture/reset controls and inspect conflict/reserved feedback announcements. Native macOS and Windows accelerator behavior requires separate native runs.
