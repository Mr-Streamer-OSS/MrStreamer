# iOS lists, guides and catch-up

On iOS (`apps/ios/src/custom-lists-screen.tsx` over `custom-lists.ts`), each list is a row under Live's Favourites, in the order made, with the count of channels that open when nonzero, and opens pushed on Live's stack (`live/list`). Holding a row in Live's list, a category, Favourites or a list, or its VoiceOver action **Lists**, opens a system sheet titled with the channel: every list, ✓ where it holds the channel (choosing it takes it out, any other adds it at the end), then **New list…**, a prompt that makes a list holding that channel and asks again, keeping the text, for a taken name or one over 60 characters. The Guide grid has no hold. A list's row plays in Watch only while its entry is still that channel at the press, else says it didn't play; an entry that doesn't open stays in place, grey, with its provider and why, and **Remove** while no longer listed. **Edit** removes and moves rows (VoiceOver actions too, buttons under the lines at accessibility text sizes); **Save** writes order and removals together or, when the list changed meanwhile, says "… changed" and writes nothing; a refused write keeps the draft for **Try again**. Rename and Delete list are in Edit and write at once; Delete pops back to Live. A channel is kept by its provider and every stream id it was seen with, so it follows a provider that drops one of its streams and never turns into another provider's; a provider removed with its history kept keeps its channels for when it is added again, and one removed with its history erased, or the Demo once erased, loses them from every list, whether or not Live is open; that erasure (`account.ts`) stays pending while the lists refuse the write, so a reset Demo finds none of them. A lists file that can't be read shows no lists and refuses every change, writing nothing over it, until it reads again at the next change, provider change or return to the app (one that reads but isn't JSON holds no lists); one a later version wrote is never written over, so an erasure waits for that version. `apps/ios/test/custom-lists-screen.test.ts` covers these journeys through the real screens and files; `custom-lists.test.ts` the model; `custom-lists-erasure.test.ts` erasure through the production account. Native visuals, the iPad popover anchor, VoiceOver and Full Keyboard Access need a native run.

On iOS, **Settings > Guides** adds up to eight external XMLTV links. **Map channels** searches channels and edits a guide id with a now/next preview. Mapped ids are tried before original ids, the provider's guide before external sources for each id. A failed catalogue offers provider-specific password or playlist-link entry, and **Try again** only for lists that failed to load, while saved mappings remain editable. A repeated `channel` route parameter uses its first value. Links stay in the Keychain; a link whose fingerprint differs from the saved guide leaves it locked. **Enter link** with the matching link restores that guide and its cached native id; a valid different link replaces it with a new guide and retires the old one. Removing a subscription withdraws its detail tokens from external guides too. An unreadable or unsupported `guides.json` keeps external caches inactive on disk for a later readable launch; known-empty state permits orphan cleanup. The `apps/ios/test/guide-sources.test.ts`, `guide-sources-erasure.test.ts`, `guide.test.ts` and `guides-screen.test.ts` contracts cover portable behavior. Native add/map/refresh/remove, matching-link restoration and different-link replacement, the bridge, disk behavior, accessibility and layouts still need device acceptance.

On iOS, a retained programme's details offer **Play from start** beside **Watch live**, and Watch offers it for the programme on now. A changed guide withdraws Watch's old action until the new listing arrives; status-only refreshes keep a valid action mounted. Watch cancels its listing read on backgrounding, starts none while backgrounded and reads again on return. Catch-up uses only channel variants that retain the programme, through the existing playback owner, adult/quality rules and provider admission. It stays labelled **Catch-up** with its airtime, uses programme-relative positions, clamps seeks to its edges and pauses at its end. For ended programmes, details explain missing or expired retention; an unavailable catch-up play fails instead of playing Live. Xtream's explicit `live: "hls"` option selects `.m3u8` archives on iOS; the desktop default remains `.ts`/`mpegts`, with the panel clock and minute rounding preserved. `apps/ios/test/playback.test.ts`, `guide-screen.test.ts`, `native-fixtures.test.ts` and `packages/core/test/xtream.test.ts` cover portable contracts. Native AVPlayer seeking on a growing EVENT playlist, real-provider availability, full-capacity/expiry admission, playlist catch-up in Watch, resize and the Watch action across programme endings and channel changes remain acceptance items; Linux stand-ins do not establish those journeys.
