# Categories, freshness and selection

For category compatibility, read `docs/user/category-compatibility.md`. `provider-categories.test.ts` exercises Xtream memberships across Live/Movie/Series; `library.test.ts` checks duplicate-category counts, unknown-reference All reachability, adult filtering, refresh and restart. Core catalogue cases keep conflicting country/language/guide metadata from joining variants. Guide suffixes use ISO countries, so `.ar` means Argentina while a reseller's `AR |` prefix can mean Arabic.

Run `pnpm verify:desktop live-categories` for the 64,000-channel/two-provider path. It gives the synthetic Sports categories explicit French/English labels, then drives Sports with Belgium and French through list, grid and Home's exact Browse action, restores the global topic without session filters, then proves All stays All after restart. It exercises Provider lists, Find, channel/programme search, favourite/history retention, playback with one provider connection, Watch's active source summary and Reset, reordered/removed categories, native restart, five locales at 960×600 and both source-removal paths with remembered global discovery. Retain PNG/AX/actions and cleanup receipts. `packages/core/test/live-browse.test.ts`, `apps/desktop/test/library.test.ts` and `preferences` cover classification, public browse membership/facets, main adult policy, exact source/order, raw future records, changed legacy baselines and both forget paths. `renderer/live-browse`, `live-categories`, `library-updates` and `live-search-grouping` cover descriptor freshness, viewing sequences, filter reset, Home fallback, native picker keys and exact owned actions. The optional raw rememberedLiveBrowse leaf stays outside general Preferences. No worker, new catalogue store or wire revision is introduced.

A newly read topic or native list in grid view must start on the exact playing source/channel once rows arrive. Changing filters in an already mounted grid must retain its selected channel while that channel remains visible. Numeric tuning searches unfiltered All with Live TV's browse policy, choosing the first owned match without changing the browsing descriptor. When Home also browses unfiltered All, loaded preferences hiding adults let numeric tuning share Home's ordinary request and cache entry. Unavailable preferences preserve viewer policy, and Home always stays ordinary. `renderer/guide-grid.test.ts`, `live-browse.test.ts` and `number-entry.test.ts` cover these paths.

Viewing freshness is checked at the query cache commit, comparing only writes concurrent with that read. A source/account change may legitimately lower the combined sequence; it must remove stale favourites and progress and allow Reload and the next favourite reorder. Equal sequences can refresh canonical IDs. `renderer/viewing-query.test.ts`, `live-browse.test.ts` and `favourite-order.test.ts` cover the public query/IPC/cache contracts and the same-completion-batch read/command case.

A channel refresh that lands while a list, favourites or history read is under way must not leave that read's older answer showing: once it settles, the list is read again when it shows, and a caller awaiting it still gets its answer. `renderer/library-updates.test.ts` holds those reads through `library.updated`; `live-categories` covers the ordinary refresh path, not this timing.

The baseline alone does not prove all category compatibility paths. In an isolated fixture session, select a category, check its count and programmes, star a channel, search it and play two quality choices. Refresh reordered rows through Settings > Subscriptions, restart the same disposable profile, and check the selected category, Favourites, Recently watched and remembered quality. Include inherited M3U `#EXTGRP` groups and resets; inherited adult entries must be absent from ordinary lists and Home. Retain screenshots and playback observations. Real-provider and installed-platform acceptance remain separate.
