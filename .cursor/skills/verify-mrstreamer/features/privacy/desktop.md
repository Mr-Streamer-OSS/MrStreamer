# Desktop consent and built-app baseline

## How to get to it

Open Settings > Privacy. Share basic usage statistics is on by default. Turn it off with the checkbox; the helper must match the delivered catalogue in `docs/telemetry.md`, and Privacy policy opens the canonical policy in the system browser. No first-use notice or upgrade prompt is shown. Settings > About retains its Privacy link.

## Driving the built app

After `pnpm build`, run `xvfb-run -a node apps/desktop/test/e2e/analytics-app.ts` on headless Linux. The helper owns an isolated profile, loopback capture endpoint and debugging ports. It drives the Settings checkbox with pointer input, observes ordinary preferences and actual capture payloads, restarts the same isolated profile, and retains screenshots, payloads, instance identity and cleanup proof under `.local/verification/analytics-*`. It uses fake provider/TMDB boundaries and a loopback release feed, with automatic updates off. Product mutations use pointer/keyboard input. Named pointer targets are resolved again after scrolling and hover, require settled geometry and a matching hit, and retain the actual mousedown target in `proof.json`. It does not advance the clock; UTC rollover of `app_active_day` is covered by the focused owner tests in `apps/desktop/test/analytics.test.ts`. Production transport is impossible for this isolated profile, even if a release bundle contains production configuration.

Require a checked default and exactly one installation_observed, one app_active_day and one app_version_observed. Re-enable observes the current version as unknown_history without repeating installation/day. Every captured raw body must equal its schema-reconstructed allowlist; the proof records the exact property-key set per event name. Drive EPG expansion, a committed favourite and a nonempty search, each with its durable fixed counter. Open the continuous fake broadcast from search; require a persisted admitted journal and no playback HTTP event until its end. Measure at least 34 seconds in Watch, a Home preview of at least 12 seconds with no summary, and return to Watch under the same run. Opening provider VOD emits exactly one ended live summary with at least 32 seconds and no more than observed wall time minus preview plus three seconds. Pause, paused seek and resume preserve the VOD journal UUID and emit no early summary. Watch offline ends that VOD with one summary and admits the next. Completed/cancelled/failed downloads retain direct outcomes. Failed title open reports exactly one typed incident and no summary for that attempt. Exercise all ten screen entries, autoplay-next, successful/failed manual update checks, update seen/dismissed, source added/refreshed and an actual owned renderer crash/reload. Quit/restart seals the final usage fragment while preserving identity; every raw HTTP body must match the allowlist.

Run once with `--observe-rollover` to also wait for an actual UTC five-minute transmission, without injected clocks. It records wall-clock boundary evidence separately; this optional natural-window wait can exceed the regular release UI scenario budget. Default verification seals usage through normal quit/restart. For a fixed six-channel surfing/browsing comparison, run `xvfb-run -a node apps/desktop/test/e2e/analytics-app.ts --volume-workload` on each built candidate. An archived old source build can be selected with `--built-desktop=/absolute/path/to/apps/desktop`; that directory must contain `source-revision.txt` naming its actual archive revision. The helper verifies the owned profile, command line and renderer path against the selected build and records its main hash. Its `volumeWorkload` observations retain actual HTTP bodies/counts/bytes, public main-process CPU/fs-write deltas and distinct observed atomic analytics temporary writes. CPU excludes renderer/GPU/FFmpeg; filesystem notification counts are not native rename-latency proof. Focused public-owner tests cover UTC rollover, Brussels/DST timestamps, rollback, channel envelopes, burst durability and exact delta counts. Then disable with the real checkbox, require no captures across restart and the same identity with no duplicate first/day observation after re-enable.

A second profile is seeded with a format-one analytics.json holding daily counts and a queued app_summary_day beside a queued installation_observed. The app must send that installation_observed unchanged, under the seeded identity, never send the summary, and rewrite the file as format two without counts. A third fresh profile faces a refusing loopback capture server: it must retry a refused event with an identical body, hold actual pending events, then clear the persisted queue through Settings opt-out and make no further requests after restart. Unpackaged build attribution is `unknown`. For a packaged executable, pass `--expected-version=<version> --expected-source=<full SHA> <executable> [app arguments]`. It pins the running main executable, resources, app.asar, renderer path, About source and actual version independently of the checkout build. Artifact signature/checksum receipts are retained separately by the release owner; executable/resource hashes do not bind an operator-named installer. Native installed acceptance stays separate. Inspect screenshots and actual local payloads. Pointer and keys perform mutations; the decoded wire capture establishes results. All five translated controls are checked by focused renderer tests; native platform acceptance remains separate.

The fixture uses a checkout-owned ffmpeg stream of the existing MPEG-TS recording; aborting the owned session ends it. No production broadcast is used for this telemetry acceptance.
