# Desktop slow startup

For the Privacy controls and migration baseline, read [Desktop consent](desktop.md).

For the slow-startup recovery check, run `xvfb-run -a node apps/desktop/test/e2e/analytics-app.ts --slow-startup` on headless Linux. It drives the real Privacy controls, restarts, legacy migration and exact loopback payload assertions while delaying each main process's first analytics file read by 1700 ms. It records `startupPrivacyOnly` and omits the separate guide/playback/action workload. The 1500 ms product deadline remains unchanged. It also restarts the retained enabled profile, records exactly one disabled boot preferences.get reply, and requires the cached Privacy checkbox to become checked after recovery without another preferences.get call. A dedicated retained opted-out launch holds that read for 5000 ms. The helper immediately enables through the checkbox, passively records the public update's fixed save error after its unchanged deadline, then requires the cached checkbox to become checked and its obsolete save error to disappear after the queued commit. `observed.lateConsentCommit` retains both IPC observations, feedback before/after the commit and the read completing after the failed update, with exactly one boot get and no refresh get. The helper restores opt-out before continuing the normal restart/re-enable proof. This proves the main-process publication reaches the renderer cache rather than being repaired by the helper's polling. This is controlled promise delay, not native slow-disk evidence, and it cannot be combined with `--native-telemetry`.

Slow-startup analytics runs install an owned filesystem probe before resuming the entrypoint from the inspector. `observed.startupIO` retains up to 32 read/directory/replace measurements per launch, with elapsed start/end times, bounded filesystem error codes, the loaded format number, cached Privacy checkbox state, passive public preference replies and that launch's loopback refusal/body count. It samples at normal quit and on failure before screenshot and cleanup, without issuing a preferences.get that could repair a stale cache. A pending read or directory scan has no end time; a format-one read followed by a coded replace failure identifies migration replacement failure; an HTTP refusal has received bodies at the refusing sink. Directory scans include the initial profile-origin read. The format probe parses at most 128 KiB and retains only 1, 2 or null. Missing samples stay null. These samples contain no paths, record bytes or identifiers, and do not establish the actor or cause of an earlier CI collision. Inspector attachment changes startup timing, so this receipt is functional evidence, not a performance measurement. Ordinary, lifecycle and native telemetry runs use --inspect without a startup break or this probe, so guide workers do not inherit a paused startup.

`analytics-startup.test.ts` checks the public owner with deterministic 200/1700 ms loading, late origin classification and rejection, real-loader migration delay/failure, bounded pending opt-out, consent ordering/re-enable, summary recovery with preserved backoff, actual recovery-write failure, and quit during loading. Public composition contracts require the final published snapshot to match durable consent after queued enable, opt-out and ABA requests outlive their callers behind initial loading. Normal-load contracts cover queued enable and opt-out behind two 1200 ms saves. They also cover saved consent followed by recovery failure, rejected saves, callback failures and close during a pending save. Retained events must keep their original body and UUID, reserve the next attempt before sending, and drain once. An actual failure remains unavailable. Native Windows filesystem acceptance still requires the installed checks below.
