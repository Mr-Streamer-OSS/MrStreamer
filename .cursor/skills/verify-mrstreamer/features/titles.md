## Personal collections

The **Collections** tab on Movies and Series (`apps/desktop/src/renderer/src/features/collections/CollectionsPage.tsx`) lists the active profile's collections with visible counts, and opens one as a poster grid in saved member order. The column offers **New collection** and each row's options menu (Rename, Move up, Move down, Delete collection). A member's poster opens details on the exact added version (`asked`); an unavailable member is dimmed, says Unavailable and is selected by pressing it. Each poster's corner ring selects it; the bar above the grid then offers Add to collection (available members only), Remove from the open collection, and Done. In details, **Add to collection** beside **Save** (`apps/desktop/src/renderer/src/features/collections/TitleCollections.tsx`) ticks the collections holding the version that plays, by subscription and provider id; another version of the same title is another member.

Every read goes through the owner-enveloped `collections.*` IPC and is refused, never shown as empty, when it fails. In details, the caller shows title-read failures at the top; the collections failure line waits until a successful title read, then offers its own Try again with the collections error. `collections.changed` re-reads only for the same profile id and revision; changes are sent for the profile the view was drawn for and refused after a switch. A refresh that marks a member for adults cancels old collection responses and drops cached content and counts, including while collection surfaces are closed. Ordinary metadata updates retain selected identities and their saving state, open menu, focus and failed-write retry. During a privacy reset, collection controls remove displayed data and block replay until fresh admission arrives; an exact selected member that remains admitted retains its pending failure, while restricted or deselected members and owner or visit changes discard obsolete action state. A failed fresh title read keeps membership intent suspended and offers Try again; only a successful absence, successful removal of its target collection, or an owner, visit or version change discards it. Loading another member page keeps controls and focus for already admitted selections; missing selections are pruned only after successful reads of all requested pages. If creating a collection succeeds while title admission is unknown, the created target is retained and Retry sends only the unfinished add with fresh exact title facts. Collection replies and writes bind their exact title facts to `apps/desktop/src/main/services/ondemand.ts` catalogue currency: accepted refreshes, source changes and worker lifetime changes invalidate suspended work, including the synchronous store transaction guard. A failed refresh before acceptance retains readable catalogue facts; unloaded or failed reads refuse. Public renderer checks are in `apps/desktop/test/renderer/collections.test.ts`. Kids approval, adult visibility, exact-source authorization, restart persistence, source erasure and profile deletion are proven by main-process cases in `apps/desktop/test/collections.test.ts` and `apps/desktop/test/profile-policy.test.ts`, not by the built window.

No `pnpm verify:desktop` scenario drives collections yet. A built-window journey uses the CDP harness in `apps/desktop/test/e2e/app.ts` with the fake provider, a scratch script under `.local/` and real clicks and keys: create a collection in the tab, add the fixture movie from its details, reopen the tab, select it and remove it. Two owned fake-provider instances on separate loopback ports can exercise same-named titles from different sources through normal subscription setup. Native macOS and Windows windows require separate proof.

## Smart collections and discovery rules (#805)

`packages/contracts/src/title-filters.ts` adds genres, inclusive year/runtime/rating bounds, source ids and watched/unwatched/in-progress to the existing quality/language/verified seam. Runtime bounds are seconds. Each exact provider version retains its own year and rating; current loaded file facts carry runtime and progress. `packages/core/src/ondemand/filters.ts` requires one eligible version and one actual file to satisfy the conjunction. TMDB genres use the existing genre mapping; missing metadata never satisfies ranges. Series runtime and watch state describe loaded episode files. Filtering does not fetch details, metadata or media.

`collections.change` accepts optional rules on create and a rules edit for an existing smart collection. Summaries include the saved rules. Smart pages derive membership from the admitted current catalogue rather than writing manual members. Member/order commands refuse smart collections. Reads retain captured owner, policy and catalogue currency checks before count/page/artwork, and failed catalogue reads refuse rather than emptying membership. Rules commit atomically in the captured profile database; failed writes retain stored rules. Manual collections retain their existing behavior.

Focused public behavior proof is in `packages/core/test/title-filters.test.ts`, `apps/desktop/test/title-filters.test.ts` and `apps/desktop/test/collections.test.ts`: exact-version conjunction, unknown ranges, current loaded runtime without detail/file requests, admitted progress, membership refresh, profile separation, kids exact-source visibility and failed rule writes.

The renderer draws Paper A3.1 to A3.11. `apps/desktop/src/renderer/src/features/titles/TitleFilters.tsx` holds every rule's menu (Genre, Year, Runtime, Rating, Watched, Source, then Quality, Language and Verified) for All, opened collections and tab search; Genre and Source are multi-pick, Year is a From/To popover applied on Enter or close, Runtime picks are inclusive second bounds (Under 90 min ends at 5399) and a note counts `unknownRuntime` while a Runtime rule is set. `apps/desktop/src/renderer/src/features/collections/SmartRules.tsx` holds All's **Save as collection** popover (one create with rules, one id per popover so Retry stores once) and the smart pane: only set rules plus **+ Rule**, Any removes a rule, edits preview their count and grid through `ondemand.collection` on `all` and never save on their own, and the Rules changed bar sends one `rules` change with Discard and Retry. In `CollectionsPage.tsx`, New collection offers Collection or Smart collection; a smart draft stays local, marked New, until its first rule is created with it. Its row offers Rename before storage, preserving the draft id, kind, rules and preview. Escape keeps its name and refusal; Enter or blur changes only the local name and returns focus to the row. A refusal belongs to the submitted name, so correcting it clears the old message without remounting the Save rules button; The draft Save action accepts an open inline name on pointer-down before saving; Rename is disabled during the pending create. A failed re-read of saved matches keeps the matches shown with their time and Try again; a failed first read keeps the Failure line. Smart summaries are left out of a title's membership menu and of the picks' Add to collection, and a smart pane offers no Remove. Smart pages have no sort control, since `collections.page` takes none. A saved source that is gone shows as Removed and can only be unpicked. Public renderer cases are appended to `apps/desktop/test/renderer/collections.test.ts` and `apps/desktop/test/renderer/title-filters.test.ts`. Cancelling + Rule returns focus to its button; choosing a rule hands focus to that rule's menu. Cancelling that new rule while it is still empty removes it and returns to + Rule; a rule given a value keeps its own trigger. + Rule stays mounted while its last offered rule is open, disabled until another choice is available. No `pnpm verify:desktop` scenario drives smart collections. A scratch CDP journey can connect two owned fake-provider instances, using the public `titlesOf` constructor option for differing source hints; this supplies a bounded method, not proof that the complete two-source journey passed. Native macOS and Windows windows require separate proof.

Smart collection freshness and recovery: commands and stored rules share `StrictSmartCollectionRules` in `packages/contracts/src/collections.ts`, refusing unknown keys, empty filters and reversed ranges. In this source version, stored smart rules failing it withhold that collection: summaries carry `withheld` (the known kind, the filters still readable one by one and enumerated problems, never unknown names or raw text) with no `rules`, total 0 and empty pages; member and order commands refuse it (`isManual` is false), and only a valid `rules` change replaces the stored bytes, which an invalid one leaves untouched. A manual collection holding a member row this version can't read is hidden from reads and commands, its rows, name and order slot kept. Unrelated collections remain usable. The Collections tab draws Paper A3.17 for it: the column row shows red Repair in place of its count, and opening it mounts `SmartPane` in repair mode (`apps/desktop/src/renderer/src/features/collections/SmartRules.tsx`) with the readable rules in the usual rule controls (+ Rule alone when none are readable; an unknown kind repairs as the tab's), a notice and one plain reason per problem, and the Repair rules bar with Save rules over a preview of the edited rules, never Discard. No saved page is read for it, and title menus and picks offer only `isManual` collections. Builds containing #834 but without this repair hide invalid smart collections with no repair UI, and still refuse the whole read for a malformed member row. Builds before #834 refuse the whole read for rules they can't parse or type-check, but may apply rules with unknown keys, empty filters or reversed ranges using only the filters they know. Proof is in `apps/desktop/test/collections.test.ts`. Current-owner viewing events invalidate saved smart lists/pages/counts and discovery/preview queries, cancelling obsolete first reads. Options failures offer Try again without losing a draft; Year, Rating, Runtime, Watched and Source remain available without catalogue choices. Discard is disabled during rule writes. To-only Year keeps its upper bound. In progress uses the viewing record's 120-second threshold; series watch rules also apply admitted manual episode marks to current exact loaded files. Movie watch rules apply the latest standing film mark across versions in one subscription, including explicit unwatched; a newer replay of any sibling restores progress classification. Quality, language and verified rules still have to match one file. Runtime uses provider/TMDB lengths from the current session's recent details cache (200 entries), lost on eviction or restart. Smart reads snapshot only loaded sources, retain required manual catalogue refusals, and exclude sources accepted after that snapshot. Manual pages, memberships and writes skip smart evaluation; returning from details or global search re-reads saved smart matches and counts with obsolete reads cancelled. Full-rule results use an LRU cache keyed by policy and local facts, holding the smart rule count Collections last captured plus two shared reads (two before any Collections read). Collections supplies retention separately from the renderer query; ordinary discovery never reads the store. Worker content/lifetime and catalogue refresh changes invalidate the cache. Focused service and renderer tests cover these paths; no additional native or installed proof is claimed.

## Film, season and series marks (#852)

Paper A3 (bulk Mark watched with Undo), drawn for details in A3.13. `apps/desktop/src/renderer/src/features/titles/EpisodeMarks.tsx` holds `useTitleMarks` and `TitleMarkNotice`, which details and History share: one `viewing.markTitles` command with an explicit `MarkScope`, then a line counting the episodes changed (a film is named, not counted) with Undo, which sends `viewing.undoMarks` with the answer's `made` under a new id. `changed: 0` says the title already stood so and offers no Undo. A failed mark or Undo keeps what shows and offers Retry under the same id; a `mark-changed` Undo says "This can no longer be undone." with no action. Replies are sent for the profile the mark was made for (`callForProfile`) and the line goes after a profile switch, an unmount or once a revision the command made no longer stands in the record last read. After each answer everything under the `viewing` query prefix is read again before the line shows. In `apps/desktop/src/renderer/src/features/titles/DetailsView.tsx` a film offers Mark watched or Mark unwatched after the collections menu once `viewing.filmMarks` answers, for its versions in the playing version's subscription only (`filmScope`); a mark hides Resume and its progress bar only while no play of any version in that subscription began after it, using the core standing-film rule. The primary action keeps keyboard focus while marks or progress load and ignores activation until they answer. A failed read allows Play from the beginning with a visible Try again error, never stale Resume. A series offers Mark season and Mark series watched or unwatched beside the season tabs once `viewing.episodes` answers, flipping to unwatched when every episode there is watched; while one is stored the episode dots and the episode line wait. The per-episode dots, rows and line are unchanged. A failed film marks read says so with Try again. Main-process behavior (atomic save, skipped titles, refusals, late checkpoints, Continue watching, restart, two subscriptions) is proven in `apps/desktop/test/viewing.test.ts` and `packages/core/test/viewing-memory.test.ts`. `apps/desktop/test/profile-policy.test.ts` covers kids bulk-scope refusal, exact film reads, Undo authorization, profile separation and history filtering after approval removal. ## Followed series (#855)

`packages/contracts/src/ipc.ts` adds `follows.state`, `follows.set`, `follows.seen` and `follows.alerts` with the `follows.changed` owner event; `SeriesFollow` and `NewEpisode` are in `packages/contracts/src/ondemand.ts`. `apps/desktop/src/main/services/series-follows.ts` keeps each profile's follows by exact source version (subscription account and provider series id), so a provider rename keeps the follow and another version is another follow. Following reads the version's current episodes through `OnDemand.listedEpisodes` as the known baseline; a failed read stores nothing. After each `OnDemand.changes`, only follows whose list entry changed (Xtream `last_modified`, mapped-playlist episode files, or a new fetch when the entry has neither) read their episodes again, at most one provider details request per accepted refresh. A failed check retries on a new fetch even if the provider restores the last successful list entry. Catalogue reads and their classification writes are serialized separately from provider episode reads, so a delayed startup check cannot overwrite a newer adult classification. Unnumbered episode alerts preserve the provider names. Episodes count by season and number, so a re-uploaded file is not new and a repeated refresh adds nothing; unnumbered episodes use file ids. Withdrawn episodes are hidden but keep their unseen identity and discovery time; re-listing restores unseen alerts without counting a new discovery, and seen episodes stay seen. A failed read keeps known and new episodes, sets `lastCheck.failed` and retries with the next fetch. Catalogue names, years and adult classifications are saved before episode reconciliation is queued, even when an earlier provider read is still pending, the episode stamp is unchanged or details fail. A metadata write refused for one changed subscription leaves the other followed series in the pass eligible for reconciliation and announcements. An unlisted version keeps its follow with `title: null`; follow state withholds adult titles from profiles that may not see them using that last classification. Reads never ask the provider. Alerts leave out adult titles and unapproved kids versions; the kids gate in `apps/desktop/src/main/ipc.ts` requires approval for state, set and seen. Mark seen sends the displayed episode identities, so a concurrent arrival stays new even with the same discovery timestamp. Background changes are forwarded with the owning active profile. Erasing an account erases its follows. No timer, account polling, OS notification or start at login exists: checks run only with the app's refreshes while it runs.

Public service proof is `apps/desktop/test/series-follows.test.ts` with the fake provider: follow, refresh with an added episode, repeated refresh, multiple unnumbered files before display grouping, partial/empty episode answers and unseen restoration with original discovery times, a later episode, seen, unfollow, rename then removal, failed details read and recovery, refused follow on a failed read, adult reclassification then withdrawal with unchanged stamps, failed details or a pending earlier episode read, a subscription edit during a catalogue read without losing another source’s reconciliation or announcement, adult exclusion from alerts, permitted adult state and a second profile's separate follows. Renderer proof is `apps/desktop/test/renderer/follow-series.test.ts`: Follow, news, Mark seen, another profile's change ignored, failed check, failed toggle and failed state read on Details, and Home's alerts with an unavailable series, Stop following and Mark seen. It also closes both follow surfaces during adult reclassification and proves a late pre-refresh answer cannot restore cached private alerts. Public IPC checks in `apps/desktop/test/profile-policy.test.ts` also cover filtered kids state/set replies, approved unavailable alerts and adult reclassification followed by withdrawal hiding both state and alerts. At source `cb8bbaad4122466a1d586e3a22b5322ef4def4dc`, an isolated built Linux window showed Follow becoming Following and Home text listing one new episode after a Settings refresh. Three harness attempts ended before Details news, Mark seen or Unfollow; these actions, keyboard and translated layouts remain unproven in the built window. The source merge with later viewing-history controls has no additional window proof. Native macOS remains a separate check.

Details: `apps/desktop/src/renderer/src/features/titles/FollowSeries.tsx` puts **Follow** / **Following** (`aria-pressed`) in a series' action row, after Save and the collections menu, for the version that plays; it waits disabled until the lists and `follows.state` answer, and a failed state read says so with **Try again** instead of a toggle. The listed-title fallback also keeps Follow / Following available when provider details fail, so an existing follow can still be stopped without details. Below the row it lists the new episodes (`S2 E5 Low Tide · …`) with **Mark seen** (`follows.seen`), says when the last check failed, and says why a follow, unfollow or Mark seen failed. Reads live in `apps/desktop/src/renderer/src/features/titles/follows.ts` under the `["follows"]` query key, re-read on `follows.changed` for the current profile and on `ondemand.updated` through the app-wide catalogue listener in `apps/desktop/src/renderer/src/lib/queries.ts` (cancelled and forgotten when the lists newly mark a title for adults, including inactive queries); commands go as the profile the controls were drawn for. Paper A frames: A3.14 (Details) and A3.15 (Home).

## Returning to where the viewer was browsing (desktop 0.0.24 development, #860)

`Browsing` in `apps/desktop/src/renderer/src/app/ui-store.ts` keeps each kind's tab, open collection and its sort, All's sort, the tab search, the filters (each kind its own) and, per layer (tab and open collection), the selected poster by `Title.key` and position with the scroll, for the surface it showed (tab, sort, search and filters). `TitlesPage.tsx` reads it as it draws; `Grid` in `CollectionGrid.tsx` and the For you, New, Genres and Services scrollers restore through `useKeptScroll` (`apps/desktop/src/renderer/src/lib/use-kept-scroll.ts`) and keep their place as they unmount, through `browsingNow`, which drops a write once the account or profile changed. `resetForAccount` and `resetForProfile` start every page over, `leaveSubscription` drops that subscription from `sourceIds` and closes its More like collection, and `closeTitleSheets` (adult titles hidden) clears search and resets both mounted tabs to their top with no kept selection or scroll spot. A key the lists no longer return keeps the position only, so hidden or removed titles are never reselected. Session only: nothing is written to disk.

Privacy query refreshes keep the mounted grid and its details focus handoff, withholding unread posters, resetting selection to the first admitted title and clearing the current and remembered scroll offset. A cold return waits for the collection total before mounting, retaining a deep saved selection. Scroll restoration waits for measured grid width and search-query readiness, or completed row data, rather than treating pending results or the first overflowing partial result as complete.

Source coverage: `apps/desktop/test/renderer/browsing-state.test.ts` (profile switch, a page unmounting after the switch, filter and selected poster through a view switch, removed subscription's source filter, adult hiding), and `title-filters.test.ts` (each kind keeps its own filters). happy-dom has no layout, so scroll restoration is not proven there. Built-window proof: with the fake provider, open Movies > All movies, set Quality, move the keys several rows down, open Live TV and return, then open a genre from Genres, scroll, press Back, and require the same tab, filter, ring and scroll; repeat after switching profile (starts over) and at 960 × 600 with larger text. No native macOS or Windows proof is claimed.

## People and film franchises (desktop 0.0.24 development, #864)
