## Personal collections

The **Collections** tab on Movies and Series (`apps/desktop/src/renderer/src/features/collections/CollectionsPage.tsx`) lists the active profile's collections with visible counts, and opens one as a poster grid in saved member order. The column offers **New collection** and each row's options menu (Rename, Move up, Move down, Delete collection). A member's poster opens details on the exact added version (`asked`); an unavailable member is dimmed, says Unavailable and is selected by pressing it. Each poster's corner ring selects it; the bar above the grid then offers Add to collection (available members only), Remove from the open collection, and Done. In details, **Add to collection** beside **Save** (`apps/desktop/src/renderer/src/features/collections/TitleCollections.tsx`) ticks the collections holding the version that plays, by subscription and provider id; another version of the same title is another member.

Every read goes through the owner-enveloped `collections.*` IPC and is refused, never shown as empty, when it fails. `collections.changed` re-reads only for the same profile id and revision; changes are sent for the profile the view was drawn for and refused after a switch. A refresh that marks a member for adults cancels old collection responses and drops cached content and counts, including while collection surfaces are closed. Ordinary metadata updates retain selected identities and their saving state, open menu, focus and failed-write retry. During a privacy reset, collection controls remove displayed data and block replay until fresh admission arrives; an exact selected member that remains admitted retains its pending failure, while restricted or deselected members and owner or visit changes discard obsolete action state. A failed fresh title read keeps membership intent suspended and offers Try again; only a successful absence or an owner, visit or version change discards it. Loading another member page keeps controls and focus for already admitted selections; missing selections are pruned only after successful reads of all requested pages. If creating a collection succeeds while title admission is unknown, the created target is retained and Retry sends only the unfinished add with fresh exact title facts. Collection replies and writes bind their exact title facts to `apps/desktop/src/main/services/ondemand.ts` catalogue currency: accepted refreshes, source changes and worker lifetime changes invalidate suspended work, including the synchronous store transaction guard. A failed refresh before acceptance retains readable catalogue facts; unloaded or failed reads refuse. Public renderer checks are in `apps/desktop/test/renderer/collections.test.ts`. Kids approval, adult visibility, exact-source authorization, restart persistence, source erasure and profile deletion are proven by main-process cases in `apps/desktop/test/collections.test.ts` and `apps/desktop/test/profile-policy.test.ts`, not by the built window.

No `pnpm verify:desktop` scenario drives collections yet. A built-window journey uses the CDP harness in `apps/desktop/test/e2e/app.ts` with the fake provider, a scratch script under `.local/` and real clicks and keys: create a collection in the tab, add the fixture movie from its details, reopen the tab, select it and remove it. The fake provider has one subscription, so a built-window run does not show two sources' same-named titles apart, and native macOS and Windows windows are not covered.

## Smart collections and discovery rules (#805)

`packages/contracts/src/title-filters.ts` adds genres, inclusive year/runtime/rating bounds, source ids and watched/unwatched/in-progress to the existing quality/language/verified seam. Runtime bounds are seconds. Each exact provider version retains its own year and rating; current loaded file facts carry runtime and progress. `packages/core/src/ondemand/filters.ts` requires one eligible version and one actual file to satisfy the conjunction. TMDB genres use the existing genre mapping; missing metadata never satisfies ranges. Series runtime and watch state describe loaded episode files. Filtering does not fetch details, metadata or media.

`collections.change` accepts optional rules on create and a rules edit for an existing smart collection. Summaries include the saved rules. Smart pages derive membership from the admitted current catalogue rather than writing manual members. Member/order commands refuse smart collections. Reads retain captured owner, policy and catalogue currency checks before count/page/artwork, and failed catalogue reads refuse rather than emptying membership. Rules commit atomically in the captured profile database; failed writes retain stored rules. Manual collections retain their existing behavior.

Focused public behavior proof is in `packages/core/test/title-filters.test.ts`, `apps/desktop/test/title-filters.test.ts` and `apps/desktop/test/collections.test.ts`: exact-version conjunction, unknown ranges, current loaded runtime without detail/file requests, admitted progress, membership refresh, profile separation, kids exact-source visibility and failed rule writes.

The renderer draws Paper A3.1 to A3.10. `apps/desktop/src/renderer/src/features/titles/TitleFilters.tsx` holds every rule's menu (Genre, Year, Runtime, Rating, Watched, Source, then Quality, Language and Verified) for All, opened collections and tab search; Genre and Source are multi-pick, Year is a From/To popover applied on Enter or close, Runtime picks are inclusive second bounds (Under 90 min ends at 5399) and a note counts `unknownRuntime` while a Runtime rule is set. `apps/desktop/src/renderer/src/features/collections/SmartRules.tsx` holds All's **Save as collection** popover (one create with rules, one id per popover so Retry stores once) and the smart pane: only set rules plus **+ Rule**, Any removes a rule, edits preview their count and grid through `ondemand.collection` on `all` and never save on their own, and the Rules changed bar sends one `rules` change with Discard and Retry. In `CollectionsPage.tsx`, New collection offers Collection or Smart collection; a smart draft stays local, marked New, until its first rule is created with it. A failed re-read of saved matches keeps the matches shown with their time and Try again; a failed first read keeps the Failure line. Smart summaries are left out of a title's membership menu and of the picks' Add to collection, and a smart pane offers no Remove. Smart pages have no sort control, since `collections.page` takes none. A saved source that is gone shows as Removed and can only be unpicked. Public renderer cases are appended to `apps/desktop/test/renderer/collections.test.ts` and `apps/desktop/test/renderer/title-filters.test.ts`. No `pnpm verify:desktop` scenario drives smart collections; the fake provider has one subscription, so a built window cannot show a Source rule across two sources, and native macOS and Windows windows are not covered.

Round 1 recovery checks: current-owner viewing events invalidate saved smart lists/pages/counts and discovery/preview queries, cancelling obsolete first reads. Options failures offer Try again without losing a draft; Year, Rating, Runtime and Watched remain available without catalogue choices. Discard is disabled during rule writes. To-only Year keeps its upper bound. In progress uses the viewing record's 120-second threshold; series watch rules also apply admitted manual episode marks to current exact loaded files. Runtime uses provider/TMDB lengths from the current session's recent details cache (200 entries), lost on eviction or restart. Smart reads snapshot only loaded sources, retain required manual catalogue refusals, and exclude sources accepted after that snapshot. Manual pages, memberships and writes skip smart evaluation; full-rule results use an eight-entry cache keyed by policy and local facts, invalidated by worker content/lifetime and catalogue refresh changes. Focused service and renderer tests cover these paths; no additional native or installed proof is claimed.
