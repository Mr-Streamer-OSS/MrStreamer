# Fixture playback measurement overlay

This opt-in tool generates four files and an identity receipt; it never edits product source.
Normal builds do not import any collector, install any observer or write an export. Do not
apply this to a daily-driver app, profile or checkout. Use a fresh task-owned container with
only synthetic fixture inputs. This does not enforce network destinations: the operator must
ensure that fixture-only precondition. No provider login, URL, title or track labels are exported.

```sh
node apps/ios/scripts/measurement-overlay.ts <full-source-SHA> <new-output-directory>
```

The output contains generated full-source copies of `playback.ts` and `loading.tsx`, plus
`measurement-records.ts` and `measurement-runtime.ts`. Copy those four into `apps/ios/src`
in the disposable exact-source build checkout. Keep `identity.json` outside the bundle.
Retain both generated bytes and original source identity. Hash the new Release bundle/Hermes
and build separately; it is an instrumented fixture artifact, never pristine released bytecode.
Unsupported anchors fail closed. A failure may leave partial output; never build from it.

Retrieve `Documents/fixture-playback-observations.json` with the existing task-owned simulator
or supported app-container tooling. There is no UI export, HTTP service or telemetry. On a
simulator, `xcrun simctl get_app_container <owned-simulator> <task-app> data` locates Documents.
Container retrieval must not bypass a physical device's lock or consent.

Native samples are captured at entry to `observe`, before its admission filters and UI mapping.
A sample can therefore describe a retired item. Sequence is the native sequence; attempt, item
and generation use a session-scoped numeric mapping. Failure kind and terminal flag survive;
private track/error details are omitted. All observation kinds survive, including ended/reset.
UI phase in context is the phase **before** processing that event, not the resulting phase.
Intent records describe requests at function entry, not acknowledged native pauses. Screen is
only whether `onScreen` names Watch; it is not OS focus. Foreground comes from the existing
lazy loading observer; absence before that observer starts is unknown.

`jsReceiptElapsedMs` is `performance.now()` relative to collector initialization. Native callback
time is unavailable in the current contract. Host send/receive brackets belong in a separate
transport ledger and do not share this epoch. Neither clock proves physical picture/audio,
source broadcast time or AVPlayer buffer ownership.

The collector stores at most 256 events and stops at that count or the first callback at/after
120 seconds. It has no idle timer or added observer. The terminal envelope states boundary drops
and that subsequent callbacks are unobserved. `end: null` is incomplete, including idle or killed
sessions. A write failure silently disables further capture to isolate playback; the last file
can be incomplete or malformed. Validate it and retain the failure, never infer a complete run.
A fresh container prevents stale-session confusion. Each event rewrites the bounded JSON file
synchronously. This is measurement overhead, not an optimization or measured equivalence; an
independent on/off perturbation measurement is still required for baseline use.

Synthetic replay tests prove export semantics only. Build/simulator proof does not establish
physical-device waiting/recovery, first presentation, audio, power or original baseline acceptance.
The owning 0.0.22 baseline remains Development / UNACCEPTED with downstream cards Blocked.
